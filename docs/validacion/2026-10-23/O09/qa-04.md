## Revisión contra las reglas 1–5

| Regla | Evidencia y límite |
| --- | --- |
| 1 · PR | Frozen install → lint → tipos → unitarias → scripts → build → bundle, seguido de bootstrap `test`, test:db, integración y Chromium; sin secrets ni environments. Smoke conservado como complemento. Las fases con servicios quedan **pendientes en GitHub**. |
| 2 · Programado/cierre | Workflow semanal/manual con Firefox/WebKit, auditoría automática de `/login` claro/oscuro, upgrade real desde checkout anterior, integración tras reconstrucción y contrato de escala. Sin SHA de esquema anterior fijado falla antes de Docker. Ensayo real **pendiente**; auditoría de todas las pantallas privadas no acreditada. |
| 3 · Preprod | Build por destino, lockfile congelado, manifiesto y plan; aplicación protegida con recibo ensayado, sin reconstruir el binario. Plantilla **deshabilitada**; destino, respaldo remoto, provisión privada y despliegue pendientes. |
| 4 · Prod | Ejecución manual independiente y environment `prod`, distinto de `preprod`; el plan revisado fija hash y commit. No reutiliza build de preprod. Aceptación previa de preprod debe constar en la autorización del release; producción **no inspeccionada ni tocada**. |
| 5 · Separación | Ninguna migración se engancha a instalación/build/start; solo comandos explícitos tras bootstrap o aplicación protegida. No se cachean `.temp`, volúmenes, conexiones ni credenciales. PR solo ejecuta migraciones sobre bases locales ficticias. |

Las discrepancias de objetivo/huella dan **3**, de historial **5**, de hash/commit/bytes **6**. El runner DB conserva sus validaciones de head, expiración, identidad, respaldo y bloqueo; no se altera el SQL aplicado. Los planes son de solo lectura: el único `--dry-run` de reconstrucción solo calcula un plan y se distingue de su `--apply` autorizado con descarte de datos ficticios.

El artefacto de PR/cierre publica únicamente manifiestos, checksums, planes/recibos locales de `test`, estados/contadores de pruebas, resultados de accesibilidad/escala y PNG ficticios. No incluye `.env*`, estado de Auth, fixtures con contraseñas, logs crudos, HTML, trazas ni backups. El manifest exige checkout limpio y verifica contenido, no sustituye la confianza en el commit ni la integridad del artifact de GitHub.
